# Security Policy

## Supported Versions

Security fixes and dependency updates are applied directly to the active `main` branch:

| Version | Supported |
| :--- | :---: |
| `main` branch (latest release) | ✅ Yes |
| Historical / tagged releases | ❌ No |

---

## 🔒 Reporting a Vulnerability

We take the security and integrity of this application seriously. If you identify a security vulnerability, please do **NOT** disclose it publicly via GitHub issues or discussions.

### How to Report
Please report security vulnerabilities privately via email to:
👉 **`maurihimanshu@gmail.com`**

Include the following information in your advisory:
1. **Description**: Clear explanation of the vulnerability and its potential impact.
2. **Steps to Reproduce**: Detailed proof-of-concept (PoC) scripts, screenshots, or step-by-step reproduction guide.
3. **Affected Components**: File paths, API endpoints, or dependencies involved.
4. **Suggested Mitigation**: (Optional) Remediation patch or suggested architectural fix.

### Response & Disclosure Timeline
- **Initial Acknowledgement**: Within **48 hours**.
- **Assessment & Triage**: Within **5 business days**.
- **Fix & Deployment**: Security patches will be merged into `main` and deployed via GitHub Actions promptly.
- **Credit**: Maintainers will gladly credit the reporter in the release notes upon mutual consent.
